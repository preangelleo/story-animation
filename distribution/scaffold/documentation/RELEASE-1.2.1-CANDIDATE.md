# 1.2.1 candidate — mixed H264 chapter carrier repair

This unreleased patch preserves the published 1.2.0 distribution and contracts. When a lossy H264 video follows a lossless still clip, direct MP4 stream concatenation can decode later frames differently even with unchanged frame counts. Chapter composition now creates a separate lossless carrier when necessary, then joins whole clips. Original clips are never overwritten; final proof still compares every decoded output frame against the ORIGINAL clips. Carrier paths and hashes are recorded for audit. Full-frame proof, PCM projection, clocks, source hashes and independent review remain required.

The regression creates only synthetic 1080p gray still/test-pattern video and silence, verifies the standalone positive control, complete mixed concatenation and unchanged original decoded frames. No real story, voice, font, account, production media or supplier request is included.

All optional learning modules remain OFF by default, configurable author routing is unchanged, and the existing style, first-frame cover, multilingual subtitle, sound and chapter contracts are retained. This patch does not expand subtitle-boundary override rules, import private daily automation, or claim live semantic/provider validation. It must pass fixed-source independent Spec and Standards review before any new release publication. No existing tag, package or hash is replaced.

Typed chapter-card burns now exclude body-caption overlays by exact half-open frame ranges, bound to the chapter revision and typed EDL. Source SRT/FA and language tracks stay unchanged. The masked entry consumes explicit --font/--font-family/--font-index arguments generated from STORY_SUBTITLE_FONT/FAMILY/INDEX, with font SHA in the derivation fingerprint and strict installed fontconfig checks. Register your user-supplied font through Fontconfig (FONTCONFIG_FILE may point to an explicit configuration). No fonts are bundled. Nonchapter burns keep the existing public tool.
